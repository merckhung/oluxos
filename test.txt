Assume syscall return address is USER_RET.
1. `ldr x0, [sp, #256]` -> x0 = USER_RET
2. `msr elr_el1, x0` -> ELR_EL1 = USER_RET
--- INTERRUPT FIRES! ---
CPU automatically:
  - ELR_EL1 = Next Instruction = Address of `ldr x0, [sp, #264]`
  - PSTATE saved to SPSR_EL1
  - Jumps to .Lirq_el1
3. .Lirq_el1:
   - `mrs x0, elr_el1` -> Saves `Address of ldr...` to stack.
   - Handles IRQ.
   - `ldr x0, [sp, #256]` -> Loads `Address of ldr...` from stack.
   - `msr elr_el1, x0` -> ELR_EL1 = `Address of ldr...`
   - `eret` -> Jumps to `ELR_EL1` (which is `ldr x0, [sp, #264]`).
4. Execution resumes at `ldr x0, [sp, #264]`.
   - `ELR_EL1` is STILL `Address of ldr...` because `eret` doesn't clear it!
5. `.Lsync_el0_64` continues:
   - `msr spsr_el1, x0`
   - `ldr x0, [sp, #248]`
   - `msr sp_el0, x0`
   - `ldp ...`
   - `add sp, sp, #272`
   - `eret`
6. `eret` JUMPS TO `ELR_EL1`!!!
   - BUT `ELR_EL1` is STILL `Address of ldr...`!
   - SO IT JUMPS BACK TO `ldr x0, [sp, #264]` IN `.Lsync_el0_64`!
